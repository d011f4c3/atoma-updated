# ADR 0005 — Local Checkout Kit comparison

Date: 2026-10-07
Status: Accepted for the owner's explicitly requested local comparison
Related: Task 0130; ADR 0004

## Decision

Allow a separate opted-in local study to hand a freshly validated checkout URL
to Shopify's official Web Checkout Kit. Pin `@shopify/checkout-kit` to
`4.0.0-alpha.4`, the available preview release inspected for this task. It has
no runtime dependencies. Its Web presentation is a popup/new tab; inline iframe
checkout is not currently available in this release.

The SDK needs the URL in client memory. This is a narrow exception to ADR 0004's
redirect-only disclosure rule, limited to `POST /api/checkout/study`. The normal
cart API and checkout flow remain unchanged. The study endpoint reuses the
existing fresh cart validation, same-origin empty form POST validation, exact
test shop/checkout host and loopback development/test runtime restrictions.
It additionally requires `ATOMA_CHECKOUT_STUDY_ENABLED=true`; production always
rejects it. The study page is unavailable in production.

The response is `no-store` and `no-referrer`, is never logged, and contains no
admin credential or direct cart reference. Keep the checkout URL only in the
active component/SDK, never local storage, analytics, local route parameters or
HTML generated by the server. Discard unused prepared URLs after a short
interval, and clear them on explicit dismissal/completion. Do not interrupt a
possible payment in progress on a timeout. Use SDK origin checks without
expanding trusted origins; silence its diagnostic logs. A native Shopify
checkout form remains the fallback and fetches its own fresh URL.

## Consequences and limits

The alpha SDK is experimental and not a launch dependency. It is dynamically
imported only by the isolated local study. No production deployment, external
API consumer, private operational data, real payment, new service, DNS change
or paid Shopify plan is authorized by this comparison. Hosted checkout
branding may be prepared in a test-shop draft configuration for visual review.
The previously tested payment flow remains the baseline.

The owner rejected the test-shop branding draft. Keep it unpublished. The
revised ATOMA checkout visual concept has no payment integration and does not
authorize replacement of Shopify Checkout. API Terms section 2.3.18 require
Shopify's express written authorization for alternative checkout/payment
processing and related API transaction recording. Section 2.3.23 also imposes
Partner Account, authentication and merchant-app/consent requirements for
receiving Checkout Kit merchant event data. Verify these before further live
SDK work or a launch decision; installing the preview package is not evidence
of eligibility. Local mocked tests do not establish remote SDK readiness.

Remove the study flag to disable exploration. Remove the study route, component
and pinned dependency if the popup approach is rejected. Public launch would
require a separate decision and verified stable vendor support.
